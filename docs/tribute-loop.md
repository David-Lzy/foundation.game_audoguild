# 贡品船循环与补体力（Windows／繁体中文或英文客户端）

## 图形界面（中文 / English）

双击 `.\tools\tribute-ui.cmd`。填准确的游戏昵称（不带公会前缀），选择等级和每批次数，再选「定时」「按次数」或「持续运行」，最后点「开始运行」。默认是 3 级、每批 8 次、定时 1 小时；「预览参数」不会操作游戏。

- 核对游戏画面为 1920×1080 后才运行。可选填游戏启动器 `.exe`，仅在没有找到游戏窗口时运行；登录须手动完成。开始前回到星图，等已有集结打完。
- 游戏内可在「头像 → 設定 → 通用 → 文字語言」选择繁體中文或 English。脚本直接识别这两套游戏文字；右上角「启动器语言」只翻译设置窗口，不会改动游戏。请在开始前切换语言，运行中不要切换。
- 所选等级必须能在当前星系搜寻。若游戏只显示 `前往` / `Go`，脚本不会自动跳星系；可换等级，或手动移动后重试。
- 红色集结未打开确认页时，只有确认已回到星图且体力读数没变，才重新搜索一次。已点黄色确认、画面不明或体力变化时，不会盲目重发。
- 每批先读体力，低于 300 才用一次第一行推荐数量；**正好 300 或超过 300 都不补**。发出集结后立即监测星图舰队栏：提交前和提交后都确认扳手原本没显示，之后**新出现**的金色扳手才算本轮战斗结束。旧扳手不算；不出现扳手时，用本轮新胜利战报兜底。不再固定等 3–4 分钟，也不把扳手当作胜利证明。结算无法确认或体力没有下降时停止。
- 界面里的「战后快捷维修」默认开启。每轮结束后若有金色扳手，只点一次，并确认星图上的维修提示消失；这会消耗已有维修模组。不出现扳手就跳过，遇到未知窗口或点后未核对到结果就停，不点购买、加速或其他确认。可取消勾选或传 `--no-repair-after-rally` 只观察不修复。
- **定时时间是收尾触发点。** 到点后不再补体力，先等已发出的集结打完；若体力仍 ≥300，只继续打到读回低于 300，不强行凑满最后一批，可能超过设定时间。正常结束会显示最终体力。收尾遇到未确认的战报、窗口变化等异常会安全停，不宣称已达到目标。
- **按次数**填的是整次运行的累计集结数，不是每批次数。例如每批 8 次、总数 12 次，会安排 8+4 次。只计已经确认结束的集结；到数后不再开新批或补体力。默认若体力仍 ≥300，可多打必要的收尾轮，日志单独列出。勾「严格不超次数」则不超上限（包括 F9 收尾），体力仍满时会提示实际读数，不再补打。
- 开始后设置窗口**不会隐藏或退出**，日志实时更新；可放在后面或另一块屏幕，不会置顶。游戏失去前台后，脚本会等键鼠空闲，再多次尝试拉回游戏；恢复后重新截图确认，不会向其他窗口或旧坐标点击。运行期间不要与脚本同时操作。若约 30 秒仍无法恢复，或鼠标已经按下时失焦，则安全停止、不重放这次操作。
- 按住 **F9** 半秒可请求正常收尾（焦点在别的普通窗口时也可按）；**F8** 急停，不能保证最终体力不满。脚本结束后游戏和设置窗口都保持打开。如要关设置窗口，先停止脚本。
- 开始时如有 Windows 管理员提示，需要用户自己确认。运行日志在项目 `artifacts\runs\tribute-cycle-*` 内，可从界面的「打开日志」查看。

也可在管理员 PowerShell 中直接调用批次脚本；不传 `--execute` 只输出计划，`--hours` 和 `--total-rallies` 都不填是持续模式：

```powershell
$python = '.\.venv-tribute\Scripts\python.exe'
& $python -X utf8 -m foundation_assistant tribute-cycle --captain '你的游戏昵称' --level 3 --batch-size 8 --hours 1 --execute
# 或按总次数；需要硬上限时加 --strict-count
& $python -X utf8 -m foundation_assistant tribute-cycle --captain '你的游戏昵称' --batch-size 8 --total-rallies 12 --execute
```

## 原有单项命令

先结束已有的同级集结并回到星图；脚本运行时不要手动另开同级集结。保留前台游戏窗口，不要用终端或其他窗口遮住游戏。当前游戏进程需要同级权限，请在**管理员 PowerShell** 运行。脚本只把游戏客户区调到 **1920×1080**，不会改 Windows 显示分辨率。

```powershell
$run = '.\tools\tribute-loop.ps1'

& $run --resize-only                          # 只调整和核对 1080p
& $run --preview                              # 默认 3 级，搜到目标即停，不点集结
& $run --preview --refill-only                # 找到药水左侧 ×数量就停，不用药
& $run --execute --refill-only                # 单独补满体力
& $run --execute --rounds 1 --captain '你的游戏昵称' --auto-refill  # 先试一轮
& $run --execute --level 4 --captain '你的游戏昵称' --auto-refill   # 4 级，循环
```

- 不带 `--preview`、`--execute` 或 `--resize-only` 时只显示计划，不操作游戏。`--rounds 0` 或省略时持续循环；按住 **F8** 半秒或切走游戏窗口会停止脚本，不会取消游戏里已经发出的集结。
- 从放大镜进入贡品船标签，拖动后读回等级，再搜寻。只有目标卡片的类型、等级和红色 `集結` 都匹配才按第一次；只在舰队评分页面上按第二次黄色 `集結`。保留当前选择的队伍、集结时长及参与设置。第二次集结可能消耗 30 行动点。
- 每轮从黄色集结起至少等 180 秒。只查看巡猎邮件列表，不打开、领取或删除邮件。只有匹配自己昵称、贡品船等级、且能从邮件显示时间核对是本轮提交后才出现的胜利战报，才开始下一轮。正式运行建议用 `--captain` 指定准确昵称（不带公会前缀）；省略时从个人资料 OCR，可能多认字符。未核对到会停，默认最多等 480 秒（`--result-timeout`）。如果游戏已有本轮胜利战报，不要为了补日志重发。
- `--auto-refill` 只在低于 30 行动点时触发；`--refill-only` 则在非满体力时补。走左上角头像 → 行动点加号 → 第一行「使用」左侧的 **×数量**，点一次后读回达到或超过上限（游戏允许批量补充后超过 300）。不会点右侧「使用」、其他行或购买；药水不足、按钮变化或没读回满值就停。
- 如果放大镜、窗口、弹窗或战报格式识别不了，回到星图再预览；脚本不会跳过识别继续点。

## 环境

请使用独立的 `.venv-tribute`，不影响其他 `.venv`。在项目目录执行：

```powershell
python -m venv '.venv-tribute'
& '.\.venv-tribute\Scripts\python.exe' -m pip install -e '.[dev]'
```

识别用到繁体、英文界面的 UI 小图和 1920×1080 版面定位，不使用固定桌面坐标。等级、行动点和邮件文本由本机 OCR 读取。英文集结按页面标题、按钮颜色和 30 行动点同时校验；补体力也只允许第一行药水左侧的推荐数量，不点 `Purchase`。请先核对 [FunPlus 游戏条款](https://funplus.com/terms-conditions/en/#anc_8) 对自动化的限制。
